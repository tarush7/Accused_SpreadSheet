ACCUSED PROFILE ROOT: 12 MAIN TABLES DEEP DIVE
========================================================================

Purpose
-------
This document explains the 12 main tables in the Accused Profile Root flow: how they link, what each table means, what each column generally represents, and which fields require lookup/master decoding.

Important identity rule
-----------------------
1. accused_vid identifies the exact accused profile row/version in t_fir_accused_info.
2. fir_reg_num + accused_srno identifies the accused person inside one FIR.
3. Most direct accused lifecycle tables link using accused_vid. Some rows also carry fir_reg_num + accused_srno as fallback/context.
4. t_accused_remand links to t_arrest_memo using arr_surr_srno, not directly to accused root.
5. t_summon_warrant is a weak/context link through fir_reg_num and needs issued-to fields to isolate accused-specific records.

Lookup reading note
-------------------
Lookup/master values are decoded using the lookup mapping available in the workbook. When the workbook gives a precise lookup source, use that source. When a column points only to the common mdm.m_lookup_masters table, the same numeric code can mean different things under different master categories, so the examples shown are possible workbook master examples, not guaranteed final UI labels for every column. Treat them as guidance until the exact API code/master category is confirmed.

Relationship summary
--------------------
- t_fir_accused_info: PK=accused_vid; parent=ROOT; FK/link=-; parent key=-; note=Root table. Other accused lifecycle tables link back here.
- t_accused_procl_offender: PK=procl_offend_srno; parent=t_fir_accused_info; FK/link=accused_vid; parent key=accused_vid; note=Direct accused branch; fallback can be fir_reg_num + accused_srno when accused_vid is not reliable.
- t_fir_multi_accused: PK=fir_multi_acc_srno; parent=t_fir_accused_info; FK/link=accused_vid; parent key=accused_vid; note=Direct mapping branch; also carries existing FIR/accused fields for cross-linking.
- t_fir_notice_requests_accused: PK=accused_person_cd; parent=t_fir_accused_info; FK/link=accused_srno / fir_accused_srno; parent key=accused_srno / fir_accused_srno; note=Notice module may store local/manual accused person data; sample has accused_srno=0/fir_accused_srno=0.
- t_freezing_order_accused: PK=accused_person_cd; parent=t_fir_accused_info; FK/link=accused_vid; parent key=accused_vid; note=Direct when accused_vid is populated; otherwise notice_req_num + accused_person_cd identifies the local freezing-order person.
- t_summon_warrant: PK=summ_warr_num; parent=t_fir_accused_info; FK/link=fir_reg_num; parent key=fir_reg_num; note=Weak FIR-level/court context; filter issued-to accused using iss_to_type_cd/accused_type_cd/person fields.
- t_arrest_memo: PK=arr_surr_srno; parent=t_fir_accused_info; FK/link=accused_vid; parent key=accused_vid; note=Direct accused arrest/surrender branch; also carries fir_reg_num + accused_srno.
- t_accused_remand: PK=remand_srno; parent=t_arrest_memo; FK/link=arr_surr_srno; parent key=arr_surr_srno; note=Child of arrest memo. Remand belongs to an arrest/surrender event, not directly to root.
- t_accused_bail_details: PK=bailer_srno; parent=t_fir_accused_info; FK/link=accused_vid; parent key=accused_vid; note=Direct accused bail branch; sample may use fir_reg_num/arr_surr_srno when accused_vid is null.
- t_accused_chargesheet: PK=chargesheet_srno; parent=t_fir_accused_info; FK/link=accused_vid; parent key=accused_vid; note=Direct accused chargesheet/final-report branch.
- t_accused_disposal: PK=accused_disposal_srno; parent=t_fir_accused_info; FK/link=accused_vid; parent key=accused_vid; note=Direct accused disposal/punishment branch.
- t_accused_appeal: PK=accused_appeal_srno; parent=t_fir_accused_info; FK/link=accused_vid; parent key=accused_vid; note=Direct accused appeal branch.
